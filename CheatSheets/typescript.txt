
Typescript is mostly a compiled language with javascript (and type
error messages) the output.  The typescript compiler (tsc) either
auto-deduces types (e.g. from initializers or control flow) or takes
types from following the variable, parameter, or function definition
with ": <type>".

There can be integration with IDEs that use type information to (e.g.)
prompt possible member functions.

Type specifications:
	* <type>[] and Array< <type> >
	* any
	* { <prop> : <type>, ... }. <prop> may be followed by ? to
	  mark it as optional. 
	* <type> | <type>: A union type.
 	* never
	* (a: <type>) => <type>
	* { <prop>: <type>; ... (a:<type>): <return type>; ...}
	  (Function with properties)

type <name> = <type>; 	   // Type alias

interface <name> <object type>

You can add "as <type>" to a value and typescript will assume it's
that type.  This is equivalent to "casting" < <type> > <value>.

const values are given a type which contains only the value they were
initialized with (called a literal type).  With unions, this allows
you to express a set of values.  "as const" suffixed to an object
gives all the properties of that object a literal type.

TS does type narrowing by control and data flow analysis.  You can
hook into this with type predicates, which is specifying the return
type of a function as <param> is <type>.  That allows TS to use how
that function is used in the control flow for type narrowing.

If operating on a union of object types where the same property has a
differently literal type in each branch, typescript can correctly
analyze control flow testing the literal type.
